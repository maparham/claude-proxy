# Claude Pro/Max Subscription OAuth via a Proxy: Technical and Policy Fact Sheet (as of 2026-09-20)

Legend: **[DOC]** = documented by Anthropic; **[RE]** = reverse-engineered / community-observed, undocumented and subject to change without notice; **[NEWS]** = press or blog reporting.

## KQ1. How Claude Code authenticates with a subscription (OAuth flow, storage, token format, expiry, refresh, headers)

### Takeaway
Claude Code uses a PKCE OAuth flow against claude.ai with a hard-coded client ID; tokens (`sk-ant-oat01-…` access, `sk-ant-ort01-…` refresh) are stored in the macOS Keychain (`Claude Code-credentials`) or `~/.claude/.credentials.json` (0600) under a `claudeAiOauth` object. Anthropic documents *where* credentials live and the precedence order, but the client ID, endpoints, header requirements and token TTLs are all reverse-engineered and have been actively hardened against spoofing since January 2026.

### Cited Findings
- **[DOC] Storage locations.** macOS: encrypted Keychain; if Keychain rejects the write (e.g., locked in SSH), fallback to `~/.claude/.credentials.json` mode 0600. Linux: `~/.claude/.credentials.json` mode 0600. Windows: `%USERPROFILE%\.claude\.credentials.json`. `CLAUDE_CONFIG_DIR` relocates the file and keys the Keychain entry to that directory. `.credentials.json` is managed via `/login`/`/logout`; to route through a custom endpoint Anthropic says to use `ANTHROPIC_BASE_URL` instead. — [Claude Code docs: Authentication](https://code.claude.com/docs/en/authentication)
- **[RE] Keychain entry.** Service name `"Claude Code-credentials"`, account `$USER`; payload is JSON `{"claudeAiOauth": {"accessToken": "sk-ant-oat01-...", "refreshToken": "sk-ant-ort01-...", "expiresAt": <epoch ms>, "scopes": [...], "subscriptionType": ..., "rateLimitTier": ...}}`; retrievable with `security find-generic-password -s "Claude Code-credentials" -w`. — [shubcodes gist (binary analysis)](https://gist.github.com/shubcodes/3c9c7ff813715aa47018bf22e7cf8cb5); [Claude-Code-Usage-Monitor issue #202](https://github.com/Maciek-roboblog/Claude-Code-Usage-Monitor/issues/202)
- **[RE] Additional fields** seen in `claudeAiOauth`: `refreshTokenExpiresAt`, `scopes`, `subscriptionType`, `rateLimitTier`. — [search summary referencing claude-code issues](https://github.com/anthropics/claude-code/issues/21765)
- **[RE] OAuth parameters (extracted from CLI binary):** client_id `9d1c250a-e61b-44d9-88ed-5944d1962f5e`; authorize URL `https://claude.ai/oauth/authorize`; token endpoint `https://platform.claude.com/v1/oauth/token`; redirect URI `https://platform.claude.com/oauth/code/callback`; scopes `user:inference user:profile user:sessions:claude_code user:mcp_servers`; PKCE S256 with 32-byte base64url verifier and state; token exchange is `application/x-www-form-urlencoded` with `grant_type=authorization_code, code, redirect_uri, client_id, code_verifier, state`; response has `access_token` (`sk-ant-oat01-`), `refresh_token` (`sk-ant-ort01-`), `expires_in` = 28800 s (8 h), `scope`, `account.uuid`, `account.email_address`, `organization.uuid`; refresh uses `grant_type=refresh_token`. Account metadata is mirrored in `~/.claude.json` under `oauthAccount.{accountUuid,emailAddress,organizationUuid}`. — [shubcodes gist](https://gist.github.com/shubcodes/3c9c7ff813715aa47018bf22e7cf8cb5)
- **[RE] Token TTL conflict.** The gist reports `expires_in: 28800` (8 h). Claude-Code-Usage-Monitor #202 says access tokens "expire every ~60 minutes". Other claude-code issues describe roughly 8–12 h access tokens and "~24 hours" observed via `expiresAt`. Treat the TTL as variable/unstable. — [gist](https://gist.github.com/shubcodes/3c9c7ff813715aa47018bf22e7cf8cb5); contradicted by [Usage-Monitor #202](https://github.com/Maciek-roboblog/Claude-Code-Usage-Monitor/issues/202) and [claude-code #42904](https://github.com/anthropics/claude-code/issues/42904)
- **[RE] Refresh-token rotation hazard.** Refresh tokens rotate on use; a second process (e.g., Claude Desktop's embedded Claude Code, or a copied credentials file) that refreshes leaves the Keychain/other copy holding a revoked refresh token, causing daily "Login expired" for the CLI. This is exactly the failure mode a proxy that shares one credential with a running Claude Code would hit. — [claude-code #94464](https://github.com/anthropics/claude-code/issues/94464); [claude-code #21765](https://github.com/anthropics/claude-code/issues/21765); [hermes-agent #98334](https://github.com/NousResearch/hermes-agent/issues/98334)
- **[DOC] Login lifetime & renewal.** Claude Code warns at startup 3 days before the `/login` credential expires (v2.1.203+; 5 days before v2.1.217). Once expired and un-refreshable, requests fail with `Login expired · Please run /login`. `/status` shows a `Login` row. — [Authentication docs](https://code.claude.com/docs/en/authentication)
- **[DOC] Long-lived token.** `claude setup-token` mints a one-year OAuth token for `CLAUDE_CODE_OAUTH_TOKEN`; requires Pro/Max/Team/Enterprise; can only make model requests (no Remote Control, no claude.ai connectors); not read in `--bare` mode. — [Authentication docs](https://code.claude.com/docs/en/authentication)
- **[RE] Headers required for the OAuth bearer to be accepted:** `Authorization: Bearer <oauth_access_token>`, `anthropic-beta: oauth-2025-04-20`, `User-Agent: claude-code/<version>`, `Content-Type: application/json`. Without the Claude Code User-Agent, requests to the usage endpoint fall into "an aggressively rate-limited bucket" (persistent 429). — [Usage-Monitor #202](https://github.com/Maciek-roboblog/Claude-Code-Usage-Monitor/issues/202); [ai-quota-tracker #6](https://github.com/metabrain/ai-quota-tracker/issues/6)
- **[RE] Server-side rejection text for OAuth outside Claude Code (since Jan 2026):** `"This credential is only authorized for use with Claude Code and cannot be used for other API requests."` The Moltis docs also note Claude Code's flow uses an internal endpoint `/api/oauth/claude_cli/create_api_key` and that the client ID is hard-coded for Claude Code with no third-party OAuth program. — [Moltis docs: Anthropic OAuth FAQ](https://docs.moltis.org/anthropic-oauth.html); [paddo.dev](https://paddo.dev/blog/anthropic-walled-garden-crackdown/)
- **[NEWS/RE] Spoofing vector that was closed.** Third-party tools (OpenCode etc.) authenticated by "spoofing Claude Code's HTTP headers" and shipping Claude Code's system prompt; Anthropic's Jan 9, 2026 change targeted this. — [zbuild.io summary](https://www.zbuild.io/resources/news/opencode-blocked-anthropic-2026); [paddo.dev](https://paddo.dev/blog/anthropic-walled-garden-crackdown/)

### Inferences
- A proxy that reads the Keychain/credentials file and forwards `Authorization: Bearer sk-ant-oat01-…` with Claude Code-like headers is technically the same thing Anthropic has been blocking since January 2026; whatever header/prompt fingerprint currently works is undocumented and can be invalidated at any time.
- Sharing a single OAuth credential between Claude Code and a proxy requires the proxy to *not* perform refreshes (or to be the sole refresher and write back to the Keychain), otherwise refresh-token rotation will break one of the two.

### Gaps
- No Anthropic documentation for the token endpoint, client ID, scopes, or the `anthropic-beta: oauth-2025-04-20` flag; all are reverse-engineered. Older community code referenced `console.anthropic.com/v1/oauth/token`; I could not confirm whether both hosts still work.
- Exact current fingerprinting mechanism (which headers/system-prompt text/betas the server checks) is not public; only the error string is.

## KQ2. The OAuth usage endpoint behind `/usage` (URL, response, fields, polling)

### Takeaway
`GET https://api.anthropic.com/api/oauth/usage` (undocumented) returns `five_hour`, `seven_day`, per-model `seven_day_opus`/`seven_day_sonnet` and `extra_usage` objects with `utilization` (0–100) and ISO-8601 `resets_at`. It is rate-limited per access token; Claude Code itself falls back to a cached "last-known usage" snapshot when the endpoint returns 429, and the documented statusline `rate_limits` object is the officially sanctioned way to surface this data.

### Cited Findings
- **[RE] Endpoint & headers.** `GET https://api.anthropic.com/api/oauth/usage` with `Authorization: Bearer <token>`, `anthropic-beta: oauth-2025-04-20`, `User-Agent: claude-code/<version>`, `Content-Type: application/json`; requires `user:profile` scope. — [Usage-Monitor #202](https://github.com/Maciek-roboblog/Claude-Code-Usage-Monitor/issues/202); [claude-code #31637](https://github.com/anthropics/claude-code/issues/31637)
- **[RE] Response shape (captured April 2026):**
  ```json
  {"five_hour":{"utilization":33.0,"resets_at":"2026-04-11T07:00:00.528743+00:00"},
   "seven_day":{"utilization":13.0,"resets_at":"2026-04-17T00:59:59.951713+00:00"},
   "seven_day_opus":null,
   "seven_day_sonnet":{"utilization":1.0,"resets_at":"2026-04-16T03:00:00.951719+00:00"},
   "extra_usage":{"is_enabled":false,"monthly_limit":null,"used_credits":null,"utilization":null}}
  ```
  — [Usage-Monitor #202](https://github.com/Maciek-roboblog/Claude-Code-Usage-Monitor/issues/202)
- **[RE] Rate limiting.** Error body `{"error":{"message":"Rate limited. Please try again later.","type":"rate_limit_error"}}`, HTTP 429, no `Retry-After`; one reporter saw 429s persist through 30 s–300 s backoffs for 30+ minutes. Issue was closed "not planned"/`invalid` as not a Claude Code bug, no Anthropic engineering response. — [claude-code #31637](https://github.com/anthropics/claude-code/issues/31637); [claude-code #31021](https://github.com/anthropics/claude-code/issues/31021)
- **[RE] Working cadence.** Community finding: "safe at 180-second intervals"; use a 180 s TTL cache plus exponential backoff on 429; limits apply per access token, not per account. — [Usage-Monitor #202](https://github.com/Maciek-roboblog/Claude-Code-Usage-Monitor/issues/202)
- **[DOC] Claude Code's own handling.** When "the request for your plan limits fails, most often because the usage endpoint is rate limited," `/usage` shows the last bars loaded on this machine within the past 60 minutes with a `Showing last-known usage` note; press `r` to retry (v2.1.208+). — [Manage costs docs](https://code.claude.com/docs/en/costs)
- **[DOC] `/usage` content.** Session block (token cost estimate; "intended for API users"); for Pro/Max/Team/Enterprise also plan usage bars, attribution breakdown (skills, subagents, MCP servers), behavior flags, loops, and a usage-credits spend row; `d`/`w` toggle 24 h vs 7 d; local figures exclude other devices and claude.ai. Background note: "Some commands like `/usage` may generate requests to check status." — [Manage costs docs](https://code.claude.com/docs/en/costs)
- **[DOC] Statusline `rate_limits` (the sanctioned surface).** `rate_limits.five_hour.used_percentage`, `rate_limits.seven_day.used_percentage` (0–100), `rate_limits.*.resets_at` (Unix epoch **seconds**, unlike the raw endpoint's ISO strings), plus `rate_limits.spend_limit.*` behind a Claude apps gateway (v2.1.251+). Present "only for claude.ai Pro and Max subscribers … and only after the first API response in the session"; each window may be independently absent and is dropped once `resets_at` passes. — [Statusline docs](https://code.claude.com/docs/en/statusline)
- **[RE] Recent change.** Community trackers reference newer per-bucket fields (e.g., `seven_day_oauth_apps`) but I found no captured payload confirming them; the Usage-Monitor capture (April 2026) shows only the fields above. — [ai-quota-tracker #6](https://github.com/metabrain/ai-quota-tracker/issues/6)

### Inferences
- Since `rate_limits` in the statusline is computed by Claude Code from the same data, a proxy that needs per-user utilization for *its own* users would have to call the undocumented endpoint per token, which both violates the credential-use policy (KQ5) and collides with the per-token 429 bucket that Claude Code itself is consuming.
- The statusline percentages are the subscriber's *account-wide* utilization, not per-proxy-user; there is no per-consumer breakdown available from Anthropic for a single Pro/Max account.

### Gaps
- No official documentation for the endpoint, its schema, or its rate-limit policy exists; Anthropic has not responded in the GitHub issues.
- Could not confirm whether the endpoint schema changed after the May–June 2026 "Agent SDK credit" bucket rollout (see KQ5).

## KQ3. Subscription mode vs API mode in Claude Code, and what changes

### Takeaway
Credential precedence is documented: cloud provider > `ANTHROPIC_AUTH_TOKEN` (Bearer) > `ANTHROPIC_API_KEY` (X-Api-Key) > `apiKeyHelper` > `CLAUDE_CODE_OAUTH_TOKEN` > Anthropic profile > `/login` subscription OAuth. In API/bearer mode the subscription-only features vanish: no plan usage bars/`rate_limits`, no `/usage-credits`, no login-expiry warnings, no claude.ai connectors or `/schedule`, and `forceLoginOrgUUID` orgs block env-credential sessions entirely.

### Cited Findings
- **[DOC] Precedence order** (1) `CLAUDE_CODE_USE_BEDROCK/VERTEX/FOUNDRY`; (2) `ANTHROPIC_AUTH_TOKEN` sent as `Authorization: Bearer` "when routing through an LLM gateway or proxy that authenticates with bearer tokens"; (3) `ANTHROPIC_API_KEY` sent as `X-Api-Key`, approved once interactively via `/config` "Use custom API key" toggle, always used in `-p` mode; (4) `apiKeyHelper` (re-run every 5 min by default; `CLAUDE_CODE_API_KEY_HELPER_TTL_MS`); (5) `CLAUDE_CODE_OAUTH_TOKEN`; (6) Anthropic profile / WIF; (7) `/login` subscription OAuth. A signed-in Claude apps gateway session outranks all. — [Authentication docs](https://code.claude.com/docs/en/authentication)
- **[DOC] `ANTHROPIC_BASE_URL`** is the documented way to "route requests through a custom API endpoint"; `.credentials.json` is not meant to be hand-managed. — [Authentication docs](https://code.claude.com/docs/en/authentication)
- **[DOC] API key over subscription.** "If you have an active Claude subscription but also have `ANTHROPIC_API_KEY` set … Claude Code uses the API key once you approve it"; `unset ANTHROPIC_API_KEY` to fall back; `/status` marks the unused credential. Cloud sessions always use subscription credentials. — [Authentication docs](https://code.claude.com/docs/en/authentication)
- **[DOC] Features lost in API/bearer mode:**
  - `/usage-credits` "isn't available with API key authentication". — [Manage costs](https://code.claude.com/docs/en/costs)
  - Statusline `rate_limits` appears only for claude.ai Pro/Max subscribers (or behind a Claude apps gateway spend limit). — [Statusline docs](https://code.claude.com/docs/en/statusline)
  - `/usage` plan bars/attribution appear "On a Pro, Max, Team, or Enterprise plan"; the Session cost block is what API users get. — [Manage costs](https://code.claude.com/docs/en/costs)
  - Login-expiry warning and `/status` Login row appear only when a claude.ai/Console login is the active credential, "not when a cloud provider, `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, or `apiKeyHelper` supplies the credential." — [Authentication docs](https://code.claude.com/docs/en/authentication)
  - claude.ai connectors and `/schedule` need the claude.ai login. — [Authentication docs](https://code.claude.com/docs/en/authentication)
  - Orgs setting `forceLoginOrgUUID` block `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN`/`apiKeyHelper` sessions at startup. — [Authentication docs](https://code.claude.com/docs/en/authentication)
- **[DOC] Cost display in API mode.** `/usage` Session block computes dollars locally at list price (or `modelPricing` managed setting, v2.1.242+); same total appears in statusline `cost` and is compared against `--max-budget-usd`. — [Manage costs](https://code.claude.com/docs/en/costs)
- **[DOC] Console-mode org controls.** Console login auto-creates a "Claude Code" workspace with spend limits and a per-member dashboard at platform.claude.com/claude-code plus the Claude Code Analytics API; Anthropic also lists LiteLLM as an LLM gateway "several large enterprises reported using" for per-key spend tracking (unaffiliated, unaudited). — [Manage costs](https://code.claude.com/docs/en/costs)

### Inferences
- The documented, sanctioned architecture for "many developers behind one gateway" is `ANTHROPIC_AUTH_TOKEN` + `ANTHROPIC_BASE_URL` pointing at an LLM gateway that bills to an API key (Console) or cloud provider, not a subscription OAuth token. In that mode, per-user quota display must come from the gateway (statusline script or gateway messages), since Anthropic's `rate_limits` are absent.

### Gaps
- Model naming differences in API mode: docs show API model ids (e.g., `claude-sonnet-4-6`) in `/usage`; I did not find documentation that subscription mode shows different model names, so "model names change" is unconfirmed.

## KQ4. Statusline: how a custom script can display external data

### Takeaway
The statusline runs any shell command, receives a JSON blob on stdin (including `rate_limits` for subscribers), and prints text; it is event-driven with a 300 ms debounce, optional `refreshInterval`, and a documented trigger when a rate-limit window's `resets_at` passes — so a proxy-supplied quota can be shown by having the script fetch/cache proxy data on its own.

### Cited Findings
- **[DOC] Configuration.** `statusLine: {"type":"command","command":"~/.claude/statusline.sh","padding":2,"refreshInterval":N}` in user or project settings; `/statusline <natural language>` generates the script; `padding` default 0; `refreshInterval` minimum 1 s, "Set this when your status line shows time-based data … or externally-sourced segments". — [Statusline docs](https://code.claude.com/docs/en/statusline)
- **[DOC] Update triggers:** conversation changes, `command` change (immediate), `refreshInterval` timer, and "A rate-limit window in the data your script last received reaches its `resets_at` time." Updates debounce at 300 ms; in-flight script is cancelled on a new trigger. — [Statusline docs](https://code.claude.com/docs/en/statusline)
- **[DOC] Stdin JSON fields** include `model.display_name`, `cost`, `context_window.{total_input_tokens,total_output_tokens,context_window_size,used_percentage,remaining_percentage,current_usage}`, `exceeds_200k_tokens`, `prompt_cache`, and `rate_limits.{five_hour,seven_day,spend_limit}.{used_percentage,resets_at}` (epoch seconds). Example: `"rate_limits":{"five_hour":{"resets_at":1738425600},"seven_day":{"resets_at":1738857600}, ...}`. — [Statusline docs](https://code.claude.com/docs/en/statusline)
- **[DOC] External data pattern.** Docs demonstrate caching slow external commands (git) to a temp file refreshed every 5 s; scripts may be bash/python/node; handle absent fields with `jq -r '.rate_limits.five_hour.used_percentage // empty'`. — [Statusline docs](https://code.claude.com/docs/en/statusline)
- **[DOC] Gateway spend limits surface.** Behind a self-hosted Claude apps gateway with spend limits, `rate_limits.spend_limit.used_percentage` (can exceed 100) and `resets_at` are injected (v2.1.251+); Anthropic documents the gateway as providing "per-user usage attribution, OTLP metrics with token counts, and per-user spend limits". — [Statusline docs](https://code.claude.com/docs/en/statusline); [Manage costs](https://code.claude.com/docs/en/costs)

### Inferences
- A proxy can expose a small HTTP/file endpoint with per-user remaining budget and the statusline script can poll it (cached, with `refreshInterval`), giving proxy users a quota display without touching Anthropic's OAuth usage endpoint.

### Gaps
- No documented hook for a proxy to *inject* values into `rate_limits` other than being a Claude apps gateway (Anthropic's own gateway product); whether a third-party gateway can emit the same headers to populate `spend_limit` is not documented.

## KQ5. Anthropic policy on account sharing / third-party use of subscription OAuth, enforcement timeline, and Team/Enterprise as the sanctioned alternative

### Takeaway
Consumer Terms forbid sharing account credentials and automated/non-Anthropic-client access; the Claude Code legal page (added Feb 19, 2026) states OAuth is "exclusively" for subscribers' ordinary use of Claude Code/native apps, and that developers "may not collect, store, or intermediate Claude.ai credentials or session tokens" or "route requests through Free, Pro, or Max plan credentials on behalf of their users", with enforcement "without prior notice". Enforcement escalated: server-side blocking (Jan 9, 2026) → ToS update (Feb 19) → legal demand to OpenCode (Mar 19) → subscription limits no longer cover third-party harnesses (Apr 4, 12 PM PT) → partial reinstatement via a separate monthly "Agent SDK credit" pool (announced May 13, effective by Jun 15, 2026). The sanctioned multi-user alternative is Claude for Teams ($25/$125 per seat monthly; $20/$100 annual; 2–150 seats) with per-member limits, org and per-user usage-credit spend caps, and a per-user spend CSV.

### Cited Findings
**Policy text**
- **[DOC] Consumer Terms (effective Oct 8, 2025):** "You may not share your Account login information, Anthropic API key, or Account credentials with anyone else or make your Account available to anyone else." Prohibits accessing the Services "through automated or non-human means, whether through a bot, script, or otherwise" except via an API key or where explicitly permitted; prohibits reselling the Services. — [Anthropic Consumer Terms](https://www.anthropic.com/legal/consumer-terms)
- **[DOC] Which terms apply:** Consumer Terms for Free/Pro/Max; Commercial Terms for Team/Enterprise/API. "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK." — [Claude Code: Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- **[DOC] Authentication and credential use:** "OAuth authentication is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications." Developers "should use API key authentication … Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow." "Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice." — [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- **[DOC] Hosting Claude Code for others:** requires Commercial Terms; binary must be unmodified with all auth methods intact; "Customers may not pay for, resell, or intermediate Claude usage on their end users' behalf. Each end user must authenticate with their own Anthropic API key, Claude subscription plan credentials, or 3P inference provider credential." Provisioning your *own API key* for your own authorized users (secrets manager, machine image) is explicitly allowed if billed to the key owner and not resold. — [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)

API keys and OpenRouter unaffected. — [paddo.dev](https://paddo.dev/blog/anthropic-walled-garden-crackdown/); [zbuild.io](https://www.zbuild.io/resources/news/opencode-blocked-anthropic-2026)

Anthropic's Lydia Hallie: "You don't pay extra. It's the same subscription, same price per month." **Single-source; verify against Anthropic's own support pages.** — [VentureBeat, May 13 2026](https://venturebeat.com/technology/anthropic-reinstates-openclaw-and-third-party-agent-usage-on-claude-subscriptions-with-a-catch)

**Team plan (sanctioned alternative)**

### Inferences
- A proxy that pools one Pro/Max OAuth credential for several people violates the Consumer Terms (credential sharing, non-Anthropic-client access), the Claude Code legal page (intermediating session tokens / routing on behalf of users), and is the precise pattern Anthropic has been blocking technically since Jan 2026 and legally since Mar 2026.
