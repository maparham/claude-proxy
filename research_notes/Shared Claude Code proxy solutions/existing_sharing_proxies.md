# Existing open-source projects for sharing one Claude Pro/Max subscription across multiple Claude Code users (proxies, gateways, limiters)

Research date: 2026-09-20. Star counts, last-push dates and README contents were pulled live from the GitHub API (`gh api repos/...`) on this date. All quoted README/doc text is from the repositories' default branches on that date.

## Key Question 1: Which projects most closely match "transparent proxy + per-user token accounting + per-user admin-set limits + interactive dashboard"?

### Takeaway
Only one project found matches all four criteria for genuine Claude Code clients on a subscription OAuth credential: **devasheeshG/claude-code-proxy** (Python/FastAPI + Next.js + PostgreSQL; transparent `ANTHROPIC_BASE_URL` proxy; per-user hashed keys; per-user monthly/lifetime token and USD budgets plus per-key RPM; event/usage dashboard; polls Anthropic's OAuth usage endpoint). It has 0 stars and the author says it is unreviewed "vibe-coded" software. The larger Chinese "拼车" (carpool) gateways **Wei-Shaw/claude-relay-service** (12.6k stars) and **Wei-Shaw/sub2api** (42k stars) also match all four (per-user API keys, token-level accounting, per-key rate/token/model limits, admin dashboards). Everything else is partial: **howincodes/claude-code-limiter** has per-user limits + dashboard but is a client-side hooks enforcer rather than a proxy and counts prompts, not tokens; **askalf/dario** and **KarpelesLab/teamclaude** are transparent proxies with per-key/per-client token attribution and dashboards but no per-user limits; **dtzp555-max/ocp** and **Shreyas-Dayal/ai-cli-bridge** have per-key limits and dashboards but wrap the `claude` CLI as a subprocess behind an OpenAI-compatible API (they cannot serve a Claude Code client transparently).

#### devasheeshG/claude-code-proxy (closest full match)
- Described as "a self-hosted Anthropic-compatible gateway for a pool of authorized Claude subscription accounts. One endpoint gives a team quota-aware routing, concurrency control, transparent failover, per-user policies, usage accounting, request archives, Telegram notifications, and an operations dashboard." — [README](https://github.com/devasheeshG/claude-code-proxy)
- Repo created 2026-06-21, 0 stars, 0 forks, AGPL-3.0, 0 open issues (no issues at all), last push 2026-09-20 — GitHub API, 2026-09-20.
- Author's status note: "This project was built quickly and entirely through AI-assisted development— plainly, it was vibe-coded. I have not personally reviewed a single line of code on `main`... We have used the proxy internally for roughly four months. During the last three months it has handled more than 20 billion tokens and about 70,000 requests for us." A `human` branch will hold only reviewed code. — [README](https://github.com/devasheeshG/claude-code-proxy)
- Client config: `"ANTHROPIC_BASE_URL": "http://localhost:8080/api"`, `"ANTHROPIC_AUTH_TOKEN": "usr_their_key_here"` in `~/.claude/settings.json`; a setup helper writes only proxy values and keeps a backup. — [README](https://github.com/devasheeshG/claude-code-proxy)
- Per-user controls: "Multiple users and multiple labelled API keys per user... Per-user monthly/lifetime token and spend budgets, plus per-key request/token limits and revocation. Hashed API keys and Fernet-encrypted OAuth/fallback credentials." Also "model allowlists, exact model rewrites, thinking levels, request modes, and access policies." — [README](https://github.com/devasheeshG/claude-code-proxy)
- Enforcement (code): per-user `rate_limit_per_minute` raises HTTP 429; `monthly_token_budget`, `lifetime_token_budget`, `monthly_spend_budget_usd`, `lifetime_spend_budget_usd` raise HTTP **403** with details such as "User monthly token budget exhausted."; per-key `rate_limit_per_minute` (default env `DEFAULT_KEY_RATE_LIMIT_PER_MINUTE=0` = unlimited) raises 429. — [backend/app/routes/proxy.py lines ~633-708](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/routes/proxy.py)
- Usage metrics recorded: `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, plus a breakdown of cache-creation into 5-minute vs 1-hour TTL buckets from the nested `cache_creation` object; per model, per user, per key, per account, with estimated cost from a pricing table ("Unknown models have no pricing entry and therefore have an estimated cost of zero"). — [backend/app/utils/usage.py](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/utils/usage.py); [README events section](https://github.com/devasheeshG/claude-code-proxy)
- SSE parsing: a streaming usage accumulator reads `message_start` (input/cache counts) and `message_delta` ("message_delta carries the authoritative final output_tokens; take the latest reported"). — [backend/app/utils/usage.py lines 85-102](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/utils/usage.py)
- OAuth: implements Claude Code's OAuth flow with client id `9d1c250a-e61b-44d9-88ed-5944d1962f5e`, authorize URL `https://claude.ai/oauth/authorize`, token URL `https://platform.claude.com/v1/oauth/token`, scope `org:create_api_key user:profile user:inference user:sessions:claude_code user:mcp_servers user:file_upload`; "OAuth refresh with serialized refresh-token rotation and reauthentication detection." — [backend/app/config.py](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/config.py); [README](https://github.com/devasheeshG/claude-code-proxy)
- Polls Anthropic's OAuth usage endpoint: `OAUTH_USAGE_URL = "https://api.anthropic.com/api/oauth/usage"` and `OAUTH_PROFILE_URL = ".../api/oauth/profile"`; a `quota_refresher.py` sidecar re-probes every account every `QUOTA_REFRESH_INTERVAL_SECONDS` (default 60). Utilization "reports on a 0..100 percent scale... normalize to a 0..1 fraction" (a code comment notes a prior bug where a `> 1.0` heuristic "wrongly read a true 1% as 100%"). — [config.py](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/config.py); [oauth.py](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/utils/oauth.py)
- Headers sent upstream: `User-Agent: claude-cli/1.0.60 (external, cli)` ("keeps OAuth requests out of the aggressively rate-limited bucket") and `anthropic-beta: oauth-2025-04-20` ("required for subscription tokens"). — [config.py lines 20-24](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/config.py)
- Synthesizes pool-level `anthropic-ratelimit-unified-5h-utilization`, `-5h-reset`, `-7d-utilization`, `-7d-reset`, `-status` response headers and a `GET /api/v1/me/usage` endpoint so Claude Code's `/usage` and statusline show pooled numbers "rather than reporting whichever account answered last." — [proxy.py lines 117-142](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/routes/proxy.py); [README](https://github.com/devasheeshG/claude-code-proxy)
- Multi-account pooling: priority-ordered accounts, "PostgreSQL advisory-lock concurrency lanes per account" (default 3 concurrent requests per account), failover on "Capacity, overload, 401, 404, 429, quota, and connection failures... before response bytes reach the client"; optional pay-as-you-go API fallbacks (per-user opt-in, off by default). — [README](https://github.com/devasheeshG/claude-code-proxy)
- Dashboard: Overview (pool health, tokens, cost, filters by date/user/model), Accounts (quota windows, reauth state), Users (drag-and-drop priority lanes, budgets), Events (paginated per-request timeline with input/output/cache tokens and cost), Team page with granular permission strings for dashboard members; Telegram notifications. — [README](https://github.com/devasheeshG/claude-code-proxy)
- Storage: PostgreSQL (SQLAlchemy/Alembic); optional S3-compatible archive of request/response bodies. — [README](https://github.com/devasheeshG/claude-code-proxy)
- Per-account egress IPs: "The proxy supports several approved public egress IPs from one EC2 instance... Selecting another target pins that Claude subscription account for inference, OAuth, quota refresh, and warm-up." — [README](https://github.com/devasheeshG/claude-code-proxy)

#### howincodes/claude-code-limiter (per-user limits, but hooks not proxy)
- Tagline: "Per-user rate limits for Claude Code — share one subscription across your team with enforced quotas, credit budgets, and a real-time dashboard"; marked "Early Beta". 53 stars, last push 2026-03-25. — [README](https://github.com/howincodes/claude-code-limiter); GitHub API
- Architecture: "It works by installing a system-level hook on each user's machine that checks limits on every prompt. The hook talks to a lightweight server you self-host." Hooks: `SessionStart` (captures model, syncs config), `UserPromptSubmit` ("THE GATE" — calls server `/check`), `PreToolUse` (kill/pause), `Stop` (increments usage). Uses `managed-settings.json` + `allowManagedHooksOnly`, root-owned files, a watchdog daemon, fail-closed. — [README](https://github.com/howincodes/claude-code-limiter)
- Metrics: counts **turns (prompts)**, not tokens: "We count **turns** (user prompts), not individual tool calls." Auto-continue counts as extra turns. — [README](https://github.com/howincodes/claude-code-limiter)
- Limits: per-model caps (`opus: 5/day`), credit budgets (default weights opus 10 / sonnet 3 / haiku 1), time-of-day rules; windows `daily`, `weekly`, `monthly`, `sliding_24h`. Block message example: "Daily sonnet limit reached for Alice. Used 20/20 prompts today..." Kill switch forces `claude auth logout`. — [README](https://github.com/howincodes/claude-code-limiter)
- Stack: Express, better-sqlite3, ws; dashboard is "vanilla HTML/CSS/JS — no build step"; "Screenshot placeholder" still in README. — [README](https://github.com/howincodes/claude-code-limiter)
- Open issues: #3 (2026-04-23) "Docker server starts healthy but /dashboard returns Cannot GET /dashboard" (dashboard assets not built/copied into the image); #2 README outdated for monorepo; #4 ToS complaint (see Key Question 3). — [Issues](https://github.com/howincodes/claude-code-limiter/issues)

#### KarpelesLab/teamclaude and 2solarmax/maxpool (multi-account pooling for one operator; attribution without limits)
- teamclaude: "Multi-account proxy for Claude Code and Codex: it pools Claude Max, ChatGPT/Codex, API-key and third-party backend accounts, and rotates on quota." 335 stars, last push 2026-09-20, MIT, Node built-ins only. — [README](https://github.com/KarpelesLab/teamclaude); GitHub API
- How it works: "The proxy picks an eligible account, injects that account's real token, and rewrites `account_uuid` in the body to match. `anthropic-ratelimit-unified-*` response headers feed the session (5h) and weekly (7d) quota view." Rotates at 98% threshold by default. — [README](https://github.com/KarpelesLab/teamclaude)
- Per-client attribution: `proxy.clientKeys` — "Optional per-client keys: `[{ "name": "alice", "key": "tc-…" }]`. Each entry authenticates exactly like `proxy.apiKey`, and the tokens its responses report are booked against `name` — per-client usage shows up under `clients` in `/teamclaude/status`". `proxy.usageDimensions` books tokens against request-header values (e.g. `x-teamclaude-project`), capped at 500 distinct values. `proxy.sessionDetail` gives a per-conversation table with tokens per weekly bucket "cache reads and cache creation included". — [docs/configuration.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/configuration.md)
- No per-client limits exist; the only cap is per-*account*: `accounts[].maxUsage` "Hard per-account usage cap: a number, or a per-bucket table like `{ "unified7d": 0.6, "unified7dFable": 0.8 }`". — [docs/configuration.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/configuration.md)
- Dashboard: `GET /teamclaude/dashboard` "serves a self-contained HTML page rendering the same data as `teamclaude status`: per-account quota bars (session and weekly, plus one bar per model-scoped weekly bucket upstream reports), rotation state, and active sessions — refreshed every few seconds." Buttons: Reload config, Probe quotas. — [docs/usage.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/usage.md)
- Storage: JSON config `~/.config/teamclaude.json` and `teamclaude.state.json` ("safe to delete since quota gets re-learned from traffic"). — [README](https://github.com/KarpelesLab/teamclaude)
- Optional residential egress: `sx.apiKey` "auto-provisions a residential proxy (egress-IP 429 workaround)"; a referral link "supports TeamClaude development". — [docs/configuration.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/configuration.md)
- maxpool (fork of teamclaude, 4 stars): "ranks accounts by remaining quota ÷ time-to-reset"; session affinity via `x-maxpool-session` header; queues requests with SSE heartbeats instead of returning 429; no per-user features; TUI only; "Importing the Claude Code CLI's own local login was removed — it shares a single-use credential the CLI keeps rotating, which broke the pooled copy." — [README](https://github.com/2solarmax/maxpool)

#### askalf/dario (multi-seat pool + named keys, no quotas)
- 542 stars, last push 2026-09-20, "500+ releases since April 2026", ~33k lines TypeScript. — [README](https://github.com/askalf/dario); GitHub API
- Transparent for Claude Code: "A genuine Claude Code request already *is* the Claude Code shape, so dario forwards it byte-for-byte — system prompt, tools, thinking, key order untouched — swapping in only the pool's credential, its billing tag and cache breakpoints." Also translates OpenAI chat/Responses shapes for other tools. — [README](https://github.com/askalf/dario)
- Named keys (since 6.8): "`dario keys create bob --seat=bobs-max --models=claude-sonnet-5,claude-haiku*`... The secret is printed once and only its hash is kept, in `~/.dario/keys.json`. The request authenticated with alice's key *is* alice's in `/analytics`, in the ledger (`dario usage --by-key`) and on every log line". Model allowlist violations return 403. — [README](https://github.com/askalf/dario); [docs/keys.md](https://github.com/askalf/dario/blob/master/docs/keys.md)
- Explicitly no per-key quotas: "Quotas per key — a share of a seat's 5-hour and 7-day window — are the obvious next step and are deliberately not in this version; the attribution they would need is." — [docs/keys.md](https://github.com/askalf/dario/blob/master/docs/keys.md)
- Metrics/storage: ledger "one small row per day, per model, per billing bucket in `~/.dario/ledger.json` — request counts and the four token buckets, never a price"; `GET /metrics` Prometheus exposition; `GET /analytics/ui` "self-contained dashboard page... refreshing every minute"; TUI control panel. — [README](https://github.com/askalf/dario)
- Reads per-model buckets off every response: "Anthropic meters each model family separately: a `5h` bucket, a `7d` bucket and a per-model `7d_<family>` bucket. dario reads all of them off every response and routes each request by the bucket that governs it". Session stickiness by hash of first message because "Claude's prompt cache is scoped to `{account × cache key}`... a **5–10× token-cost multiplier**". — [README](https://github.com/askalf/dario)
- Overage guard: halts the proxy if any response bills to a claim other than `five_hour`/`seven_day` (and variants). — [README](https://github.com/askalf/dario)
- Open issue #1318 (2026-09-14) "Multiple api keys" is open. — [Issues](https://github.com/askalf/dario/issues)

#### dtzp555-max/ocp (CLI wrapper with per-key request quotas and dashboard)
- "OCP translates OpenAI-compatible `/v1/chat/completions` requests into `claude --output-format stream-json` CLI calls. Anthropic sees normal Claude Code usage". "Drives the official CLI as-is, no binary patching... Traffic therefore looks like genuine Claude Code to Anthropic's classifiers (`cc_entrypoint=cli`)." 113 stars. — [README](https://github.com/dtzp555-max/ocp)

- Storage: `~/.ocp/ocp.db` (SQLite via `node:sqlite`, requiring Node 22.13+). Dashboard `/dashboard` "for real-time per-key usage, request history, plan utilization, and system health"; `ocp usage` shows "Plan Usage Limits". — [README](https://github.com/dtzp555-max/ocp)
- Auth tiers: `none`, `shared`, `multi` ("per-user keys with usage tracking"); "The per-key modes give usage tracking, quotas, and cache separation — **not** a security isolation boundary." — [README](https://github.com/dtzp555-max/ocp); [docs/lan-mode.md](https://github.com/dtzp555-max/ocp/blob/main/docs/lan-mode.md)

#### Wei-Shaw/claude-relay-service and Wei-Shaw/sub2api (large Chinese carpool gateways)
- claude-relay-service (12,633 stars, created 2025-07-14, last push 2026-09-20, JavaScript, Redis 6+): positioned for "找朋友拼车: 三五好友一起分摊Claude Code Max订阅" (carpooling: 3-5 friends splitting a Max subscription). Features: "多账户管理" (multiple Claude accounts auto-rotate), "自定义API Key: 给每个人分配独立的Key" (a separate key per person), "使用统计: 详细记录每个人用了多少token" (per-person token usage), cost converted at official prices. Per-key limits at creation: "速率限制: 限制每个时间窗口的请求次数和Token使用量" (rate limit on requests and tokens per window), "并发限制" (concurrency), "模型限制" (model list), "客户端限制" (client restriction by User-Agent, e.g. ClaudeCode, Gemini-CLI). Web UI at `/web`. Account-level 503/5xx cooldown overrides in admin. — [README](https://github.com/Wei-Shaw/claude-relay-service); GitHub API
- sub2api (42,134 stars, created 2025-12-18, Go, PostgreSQL 15+ / Redis 7+): "AI API Gateway Platform for Subscription Quota Distribution... - ben-vargas/ai-cli-proxy-api (fork of router-for-me/CLIProxyAPI, 52,594 stars, 640 open issues): Go multi-provider OAuth gateway; "Since v6.10.0, CLIProxyAPI... no longer ship built-in usage statistics. If you need usage statistics, use: CPA Usage Keeper (SQLite storage, aggregate APIs, built-in dashboard)" or CPA-Manager. — [README](https://github.com/ben-vargas/ai-cli-proxy-api)
- tokengateway: LiteLLM plugin approach; describes "Rotating Refresh Token Drift: Anthropic rotates `refresh_token` single-use credentials; multiple processes refreshing tokens cause race conditions and premature auth invalidation (`400 invalid_grant`)"; README lists its own critical finding TG-001: credential API endpoints "have **no authentication**" (later notes say it was removed). — [README](https://github.com/eduardopessin/tokengateway)
- zsio/claude-code-hub (170 stars, last push 2025-10-27, stale): multi-tenant users, RPM limit and daily USD quota per user, Shadcn admin UI, PostgreSQL. — [README](https://github.com/zsio/claude-code-hub)
- Additional related repos surfaced on GitHub topics `claude-code-proxy` / `claude-max` (not deeply examined): rynfar/meridian (2,030 stars, Claude Max in OpenCode/Aider etc.), lich0821/ccNexus (974), carlosadrianosj/HydraHub (4, "usage-aware load balancing"), AuvaLabs/claude-bridge (3), evrenverse/claude-rotate (4, "picks the account with most 5h/weekly quota headroom"). — GitHub topic search results, 2026-09-20 ([topic:claude-code-proxy](https://github.com/topics/claude-code-proxy), [topic:claude-max](https://github.com/topics/claude-max))

### Inferences
- The design space splits cleanly: (a) transparent `ANTHROPIC_BASE_URL` proxies that inject a subscription OAuth token (devasheeshG, teamclaude/maxpool, dario, CC-Router, CRS, sub2api); (b) CLI subprocess wrappers exposing OpenAI-compatible APIs (ocp, wende, thhuang, RichardAtCT, ai-cli-bridge), which serve non-Claude-Code clients and cannot be a drop-in for the Claude Code CLI; (c) client-side hook enforcement (claude-code-limiter), which never sees tokens.
- The most mature per-user accounting + limits + dashboard implementations for transparent Claude Code proxying are the Chinese carpool gateways (CRS, sub2api) and devasheeshG's proxy; the English-language multi-account proxies (teamclaude, dario) have deliberately stopped at attribution and not added per-user limits.
- Token-based per-user budgets are enforced pre-request from historical ledgers (devasheeshG checks month-to-date totals before forwarding), which means the last request that crosses a budget is still served; none of the projects implement mid-stream cut-off.

### Gaps
- Could not verify CRS's or sub2api's exact enforcement semantics (status code/message on per-key limit breach) or their SSE usage-parsing details from READMEs alone; their source was not inspected.
- ben-vargas/ai-cli-proxy-api's per-key limit capabilities were not verified (README defers to the management API docs at help.router-for.me).
- No Hacker News or Reddit threads specifically about claude-code-limiter, teamclaude, dario or devasheeshG/claude-code-proxy were found via web search; community reception could not be assessed.

## Key Question 2: Does any project attribute the account's real quota percentage to individual users (share-of-account limits)? How?

### Takeaway
No. None of the surveyed projects convert Anthropic's per-account 5-hour/7-day utilization into a per-user share or enforce a per-user percentage of the account's quota. Projects that read the utilization (teamclaude, maxpool, dario, devasheeshG) use it only for account selection/rotation and pool-level display; per-user controls are implemented instead with proxy-local counters (prompts, credits, requests, tokens, USD).

### Cited Findings
- dario explicitly names the missing feature: "Quotas per key — a share of a seat's 5-hour and 7-day window — are the obvious next step and are deliberately not in this version; the attribution they would need is." — [docs/keys.md](https://github.com/askalf/dario/blob/master/docs/keys.md)
- teamclaude supports percentage caps only per **account** (`accounts[].maxUsage`, e.g. `{ "unified7d": 0.6 }`), and per-client keys only book tokens ("the tokens its responses report are booked against `name`") without limits. — [docs/configuration.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/configuration.md)
- devasheeshG's per-user limits are absolute token/USD/RPM budgets (`monthly_token_budget`, `monthly_spend_budget_usd`, `rate_limit_per_minute`), while account utilization from `/api/oauth/usage` drives rotation thresholds (`DEFAULT_FIVE_HOUR_ROTATION_THRESHOLD = 1.0`, `DEFAULT_WEEKLY_ROTATION_THRESHOLD = 1.0`) and is re-exported as pooled `anthropic-ratelimit-unified-*` headers. — [proxy.py](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/routes/proxy.py); [config.py](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/config.py)
- claude-code-limiter approximates cost weighting with admin-configured credits per prompt ("opus costs 10, sonnet costs 3, haiku costs 1") — not a measured share of the account. — [README](https://github.com/howincodes/claude-code-limiter)
- ocp caps per-key **requests** only and notes "All users share your Claude Pro/Max **rate limits** (5h session + 7d weekly)". — [docs/lan-mode.md](https://github.com/dtzp555-max/ocp/blob/main/docs/lan-mode.md)
- The utilization signal itself is available on every response: `anthropic-ratelimit-unified-5h-utilization: 0.38`, `anthropic-ratelimit-unified-7d-utilization: 0.81`, `anthropic-ratelimit-unified-representative-claim: seven_day`, `anthropic-ratelimit-unified-fallback-percentage: 0.5`, `anthropic-ratelimit-unified-7d-surpassed-threshold: 0.75`, plus overage status fields. — [dario discussion #1, 2026-04-08](https://github.com/askalf/dario/discussions/1)
- Per-model weekly buckets exist and are tracked by teamclaude ("Tracks the per-model weekly cap separately, so an account out of Fable quota is skipped for Fable requests") and dario ("a per-model `7d_<family>` bucket"). — [teamclaude README](https://github.com/KarpelesLab/teamclaude); [dario README](https://github.com/askalf/dario)
- Reported OAuth utilization "arrives on a whole-percent grid, so a fraction only changes the outcome for an API-key account, whose used share is continuous". — [teamclaude docs/configuration.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/configuration.md)

### Inferences
- A share-of-account limiter would need to attribute each response's *delta* in the account's utilization header to the requesting user (or infer it from tokens weighted by model), which is complicated by whole-percent granularity, per-model weekly buckets, concurrent requests from multiple users landing between header readings, and cache reads/creation counting differently — likely why every project has fallen back to proxy-local token/request counters.
- teamclaude's per-account `maxUsage` shows the mechanism (compare a utilization fraction against a cap per bucket) already exists at account granularity; the missing piece across all projects is per-user apportionment.

### Gaps
- No public documentation from Anthropic on how the utilization percentage is computed from tokens per model was found in this research, so the feasibility of exact per-user apportionment could not be assessed from primary sources.

## Key Question 4: What design lessons or pitfalls do issues and READMEs reveal (token refresh, streaming, headers, beta flags, request signing, model aliasing)?

### Takeaway
Recurring lessons: refresh tokens are single-use and rotate, so exactly one refresher must own each credential (and never share the CLI's own login); usage must be read from both `message_start` and `message_delta` SSE events and include cache tokens; SSE parsers must be bounded; a `429` has at least three distinct meanings (quota bucket spent, per-minute throttle, request-scoped refusal) that require different reactions; requests must carry Claude Code's `User-Agent`, `anthropic-beta: oauth-2025-04-20` and per-model beta sets, and `account_uuid` in the body must match the injected token; prompt cache is scoped per account so account rotation costs a cache miss; and Node's global `fetch` HTTP/2 multiplexing stalls under many concurrent 1 MB Claude Code uploads.

### Cited Findings
- Single-use refresh tokens: "Refresh tokens are single-use, so two replicas refreshing the same seat leave one holding a dead token; the optional refresh lock (Redis or Cloudflare) makes the loser adopt the winner's credentials." — [dario README](https://github.com/askalf/dario). tokengateway: "Anthropic rotates `refresh_token` single-use credentials; multiple processes refreshing tokens cause race conditions and premature auth invalidation (`400 invalid_grant`)". — [tokengateway README](https://github.com/eduardopessin/tokengateway). maxpool removed CLI-credential import because "it shares a single-use credential the CLI keeps rotating, which broke the pooled copy. Use browser login so maxpool holds its own independent grant." — [maxpool README](https://github.com/2solarmax/maxpool). devasheeshG: "OAuth refresh with serialized refresh-token rotation and reauthentication detection." — [README](https://github.com/devasheeshG/claude-code-proxy)
- Client token refresh passthrough: "Client token refresh requests (`/v1/oauth/token`) are relayed to upstream untouched — the proxy and client manage their own token lifecycles independently." — [teamclaude docs/routing.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/routing.md). Open issue #395 (2026-09-14): "Base-URL mode fails before reaching proxy when local Claude OAuth expires" (the client still needs its own valid login). — [teamclaude issues](https://github.com/KarpelesLab/teamclaude/issues/395)
- SSE usage parsing: read `message_start` for input/cache counts and `message_delta` for authoritative `output_tokens`; also parse nested `cache_creation` for 5m vs 1h TTL buckets. — [devasheeshG usage.py](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/utils/usage.py). Pitfall: teamclaude #341 (closed 2026-09-09) "SSE usage-parser accumulates an unbounded string when an upstream stream has no blank line — multi-GB RSS and an uncatchable OOM abort". — [teamclaude issue #341](https://github.com/KarpelesLab/teamclaude/issues/341)
- Count cache tokens: "a sum of `input_tokens` and `output_tokens` understates a cached Claude Code session by orders of magnitude." — [teamclaude docs/configuration.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/configuration.md)
- Three kinds of 429: "A **quota rejection** (a spent 5h or weekly bucket, `unified-…-status: rejected`) switches accounts immediately. A **rate-limit 429** (the per-minute throttle) does **not** switch... A **request-scoped 429** — no `retry-after` and no `anthropic-ratelimit-*` headers at all, which is how upstream refuses a model id it will not serve — is about the request, not the account." Issue #288: "A request-scoped 429 is amplified into a fleet-wide stall: fabricated 60s retry-after plus an account-wide pause". — [teamclaude docs/routing.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/routing.md); [issue #288](https://github.com/KarpelesLab/teamclaude/issues/288)
- 403 entitlement denial: `error.details.error_code: oauth_not_allowed_for_organization` means the org disallows OAuth; teamclaude quarantines the account 5 minutes. Issue #412: a 401 was relayed to the client while the account stayed in rotation. — [docs/routing.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/routing.md); [issue #412](https://github.com/KarpelesLab/teamclaude/issues/412)
- Fail over before first byte: failures are handled "before response bytes reach the client" (devasheeshG); dario 6.1 added mid-stream continuation because "bytes were on the wire, so the socket reset... ended the stream where they happened, with no `message_stop`, and the client threw away every word it already had." — [devasheeshG README](https://github.com/devasheeshG/claude-code-proxy); [dario README](https://github.com/askalf/dario)
- Headers/beta flags: `User-Agent: claude-cli/1.0.60 (external, cli)` "keeps OAuth requests out of the aggressively rate-limited bucket; the oauth beta header (`oauth-2025-04-20`) is required for subscription tokens." — [devasheeshG config.py](https://github.com/devasheeshG/claude-code-proxy/blob/main/backend/app/config.py). dario's drift log: "`context-1m` dropped from the default beta set on the OAuth path" (v3.38.3-4) and "Per-model `anthropic-beta` sets — Proxies sending one set diverge for non-Opus models" (v4.8.53); dario captures the wire shape "live from your own installed `claude` binary on every startup". — [dario README](https://github.com/askalf/dario)
- Body rewriting: "rewrites `account_uuid` in the body to match" the injected token; CC-Router issue #3 "account_uuid is empty". — [teamclaude README](https://github.com/KarpelesLab/teamclaude); [CC-Router issue #3](https://github.com/VictorMinemu/CC-Router/issues/3)
- Prompt cache scoping: "The prompt cache is scoped to the account/organization that created it and expires after a few minutes, so the first turn after a switch is a cache **miss**... No proxy can share a cache across organizations." Pin conversations, not client sessions, because "Claude Code sends the same session id for its own turns and for every subagent it launches" (issue #109). — [teamclaude docs/routing.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/routing.md). Users seeing higher usage through a proxy: "Almost always the prompt-cache TTL... `DARIO_CACHE_TTL_1H=1` forces the 1-hour TTL." — [dario README](https://github.com/askalf/dario). devasheeshG exposes `ENABLE_PROMPT_CACHING_1H=1`. — [README](https://github.com/devasheeshG/claude-code-proxy)
- Transport: "Node's global `fetch` instead multiplexes every request to `api.anthropic.com` over a **single HTTP/2 connection**; under many concurrent large uploads (Claude Code POSTs ~1 MB of context per turn) that one connection serializes... and a trivial request can wait minutes for headers ([#106])." teamclaude uses pooled HTTP/1.1. — [docs/configuration.md](https://github.com/KarpelesLab/teamclaude/blob/main/docs/configuration.md)
- Keep clients alive while queued: maxpool "Queued streaming requests receive SSE heartbeats, preventing Claude Code's client timeout from abandoning temporary waits"; non-streaming requests capped at 5 min "They have no SSE keepalive". — [maxpool README](https://github.com/2solarmax/maxpool)
- Pooled `/usage` reporting: devasheeshG synthesizes pool-level `anthropic-ratelimit-unified-*` headers and `GET /api/v1/me/usage` so the statusline is consistent. — [README](https://github.com/devasheeshG/claude-code-proxy)
- Hardcoded endpoints: teamclaude "Catches hardcoded `api.anthropic.com` endpoints (the Claude Design MCP, for one) through a local MITM forward proxy, not only what `ANTHROPIC_BASE_URL` covers." — [README](https://github.com/KarpelesLab/teamclaude)
- Model aliasing: devasheeshG uses a "Deterministic model catalog" (local `GET /api/v1/models`) "so opening Claude Code does not wait for every account"; per-user "exact model rewrites are rendered in events as `target (requested)`". dario resolves `opus`/`sonnet`/`haiku`/`fable` shortcuts and `[1m]` variants. — [devasheeshG README](https://github.com/devasheeshG/claude-code-proxy); [dario README](https://github.com/askalf/dario)
- Security pitfalls in proxies: teamclaude #324 "The loopback auth exemption is granted to the whole internet behind a same-host reverse proxy"; #420 "A mistyped /teamclaude/ path is forwarded upstream with an account credential"; #314 "WebSocket upgrade handler is registered outside the API-key gate". ocp #328 "the proxy's own PROXY_API_KEY is inherited by every spawned claude, so a prompt-injected child holds a valid credential for the proxy". — [teamclaude issues](https://github.com/KarpelesLab/teamclaude/issues?q=is%3Aissue); [ocp issue #328](https://github.com/dtzp555-max/ocp/issues/328)
- Reverse-proxy header gotcha for sticky sessions: "Nginx drops headers containing underscores by default (e.g. `session_id`), which breaks sticky session routing in multi-account setups." — [sub2api README](https://github.com/Wei-Shaw/sub2api); same note in [claude-relay-service README](https://github.com/Wei-Shaw/claude-relay-service)
- Quota semantics: `representative-claim` tells which window is binding; `fallback-percentage: 0.5` "means only 50% of capacity is available. In practice, this means Opus and Sonnet return 429 while Haiku keeps working." — [dario discussion #1](https://github.com/askalf/dario/discussions/1)
- Quota-limit enforcement race: ocp notes per-key quotas "are best-effort. Under concurrent bursts a key can exceed its cap by up to the server's max-concurrency (default 8), and cache hits are not counted toward quota." — [docs/lan-mode.md](https://github.com/dtzp555-max/ocp/blob/main/docs/lan-mode.md)
- Hooks-based enforcement pitfall: claude-code-limiter's Docker image did not ship the dashboard build (`Cannot GET /dashboard`), and its README still contains a "Screenshot placeholder". — [issue #3](https://github.com/howincodes/claude-code-limiter/issues/3); [README](https://github.com/howincodes/claude-code-limiter)

### Inferences
- A per-user token-accounting proxy for genuine Claude Code clients should: hold its own OAuth grant (not the CLI's), serialize refreshes, forward Claude Code's request shape unchanged except for `Authorization`/`account_uuid`, parse `message_start` + `message_delta` (with cache buckets) from a bounded SSE parser, record the `anthropic-ratelimit-unified-*` headers per response, and distinguish quota 429s from throttle 429s before deciding whether to surface them to users.
- Request signing does not appear as a concern in any surveyed project; the auth mechanism is a bearer OAuth access token plus the beta header and User-Agent, and no project mentions cryptographic request signatures.
