بعضی کارها سبک نیستند: ساختن نسخه اول یک اپلیکیشن، بازنویسی یک کد قدیمی، یا تمام کردن پروژه‌ای که فردا باید تحویل بدهید. در این کارها کلاد ساعت‌ها پشت سر هم کد می‌خواند، می‌نویسد و تست می‌کند و توکن زیادی مصرف می‌شود. بسته استاندارد برای همین ساخته شده: هر روزش دو برابر مصرف یک روز کلاود پرو سهمیه دارد.

کارهایی که در یک روز بسته استاندارد جا می‌شوند

  • MVP یا نمونه اولیه: یک API با پنل ادمین، یک ربات تلگرام کامل، یا یک لندینگ پیج با فرم ثبت نام.
  • ریفکتور بزرگ: انتقال کد قدیمی به فریم‌ورک تازه، اضافه کردن تایپ و نوشتن تست برای بخش‌های حساس.
  • قبل از ددلاین: تمام کردن پروژه پایان‌نامه یا تحویل پروژه فریلنسری در یک شب.
  • هکاتون: از ایده تا دموی کارکردنی، بدون این‌که وسط کار سهمیه تمام شود.
  • کار روی حجم زیادی از متن: خلاصه و تحلیل ده‌ها فایل، یا ترجمه کامل یک سند طولانی.

چطور از یک روز بیشترین استفاده را ببرید

  1. قبل از شروع بسته، در یک فایل کوتاه بنویسید محصول چه کاری باید بکند و چه چیزهایی فعلاً لازم نیست.
  2. با gclaude از کلاد بخواهید اول یک برنامه کار بنویسد و بعد قدم‌به‌قدم پیش برود.
  3. بعد از هر قدم تست‌ها را اجرا کنید و تغییرات را در git کامیت کنید تا راه برگشت داشته باشید.

MVP، هکاتون یا ددلاین فردا
پروژه کامل یا ریفکتور چندروزه

کِی بسته هفتگی بهتر است؟

اگر پروژه بیشتر از یک روز کار دارد، مثلاً یک پروژه کامل فریلنسری از طراحی تا دیپلوی، یا آماده کردن پورتفولیوی گیت‌هاب قبل از اپلای، بسته استاندارد هفتگی هم ارزان‌تر از هفت بسته روزانه است و هم خیال‌تان را از سهمیه راحت می‌کند.
